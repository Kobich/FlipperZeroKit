# Работа с FlipperZeroKit

- Общаемся по-русски, последовательно и по делу; пользователь — Android-разработчик.
- Рабочий проект — этот каталог. Соседний Flipper-Zero-Companion принадлежит коллеге: только чтение; не переключать его ветки, не править и не собирать его рабочую копию.
- Фундамент функционального объёма — docs/TASK.md: приложение-передатчик, восстановление связи при повторном входе, информация/заряд, список и получение файлов, отправка с телефона, прогресс и результат. Исходный снимок сохранён в docs/requirements/original-task.png.
- Перед продолжением прочитать README.md, docs/TASK.md, docs/ROADMAP.md и docs/VALIDATION.md; BASELINE.md содержит историю исходника. Новые указания пользователя имеют приоритет над записанным планом.
- Актуальная основа — origin/protobuf-framing, commit 5d4be58d628b68249cd7d744c445143f4b686618. ble-transport уже влита в main. В main framing/ping нет, поэтому не судить о готовности по одной main.
- Единая фича — один Gradle-модуль :flipper: BLE/RPC/framing/protobuf + UI в dev.flipper.ui. :sample — только хост с Hilt/темой/внешней навигацией и владельцем Flipper. Demo-данных и отдельного :flipper-ui нет.
- Ping найден и перенесён; по проверке пользователя он работает. Собственного физического прогона пока нет.
- В нашем модуле getDeviceInfo уже реализован через internal/rpc/RpcClient; demo убрано. Исходная закомментированная попытка описана исторически в BASELINE.md. Текущий API и проверка — docs/DEVICE_INFO.md.
- 24.11.2026 по просьбе пользователя реализован пробный сквозной вариант: reconnect в sample, PowerInfo, подтверждённый PingResponse, Storage.List/Stat/Read/Write/Md5sum, SAF, прогресс/отмена. Mock-каталог удалён. Пользователь затем подтвердил успешный прогон и явно скачивание; отправку ещё не проверял. Следующая работа — физически проверить отправку с MD5/обратным скачиванием, отдельно autoreconnect/ошибки, записать firmware. Не выдавать положительный общий отзыв за приёмку всех крайних сценариев.
- Не выдавать успешную отправку за RPC-ответ и не считать demo-значения данными девайса.
- После работы обновлять статус и фактические результаты проверок в docs.
- Уточнение пользователя имеет приоритет над прежним разделением: Compose разрешён в едином :flipper, внутри ui/. BLE/RPC-пакеты api/internal не импортируют UI. Модуль не требует Hilt и не создаёт Activity/глобальные бары/NavController. Хост владеет клиентом; стандартный reconnect/saved device находятся в ui/internal/connection/ConnectionViewModel, необязательный controller позволяет заменить политику.

- Имя Gradle-модуля и каталога — flipper. Публичный контракт — dev.flipper.api.Flipper, модели — api/model, реализация — internal. Не возвращать в библиотеку прикладные data/domain/repository или отдельную FlipperZeroClient-фабрику.

- Плановую трактовку скачивания файлов, выбор путей, конфликт имён и поведение передачи в фоне не выдавать за дословные требования исходника: рабочие допущения и вопросы записаны в TASK.md. UI-блок находится внутри единого :flipper; :sample — демонстрационный хост. Не выделять ui в отдельный Gradle-модуль без нового указания пользователя.

- 24.11.2026 выполнена очистка warning: compiler 0, Lint sample 0/0, Lint flipper 0 ошибок/3 GradleDependency (Hilt), 17 тестов и AAR/APK прошли в рабочем проекте. Hilt 2.59+ требует AGP 9; обновлять сборочный стек согласованно. Подробности и локальные compatibility suppressions — docs/WARNINGS.md; глобальные проверки не отключать.

- Последние решения пользователя 24.11: автонумерация имён (2)/(3), удаление partial через durable journals, мягкая отмена upload на границе кадра/Delete; для read/сбоя — восстановление и cleanup. Foreground connectedDevice service владеет передачей; ViewModel/навигация её не отменяют. Без общего 10-минутного лимита; технические watchdog/transport timeout остаются. Один файл, ASCII, без resume, без ограничения каталогов. Общий экран с блоками вместо вкладок. Таблица решения/реализация/остаток — TASK.md §7.

- Добавлен getKnownDevices(): сопряжённые BLE/dual/unknown + системно подключённые GATT, чтение без сканирования/сброса сессии. UI показывает оба признака раздельно. Для списка, direct connect и autoreconnect использовать connectPermissions; requiredPermissions оставлен для поиска. Не считать системное GATT-подключение готовой RPC-сессией и не удалять bond при попытках. RSSI сохранённых устройств null. Sample 1.1-prototype (versionCode 2).

- RPC-ready теперь имеет отдельный таймаут 15 с после CCCD; это закрывает прежний пункт бесконечного ожидания. Default recovery учитывает выбор/отключение пользователя. Reconnect видимой фичи: до 3 попыток 0/2/6 с, cooldown 60 с; после явного disconnect/поиска автоматическое подключение выключено до ручного выбора.

- 24.11.2026 уточнён R09: во внешнем нижнем баре один Flipper, FlipperScreen теперь общий экран с блоками устройства/файлов. Задача передачи принадлежит сервису, UI ViewModel — внешнему destination. Lifecycle хуки controller привязаны к входу/выходу фичи, не только Activity. Sample 1.4-prototype (5). Контракт — flipper/README.md; 46 тестов A/B/U/P/F с шагами и контрольными файлами — docs/PROTOTYPE.md. Не требовать от удалённого пользователя намеренно рвать связь без возможности восстановления.

- Последнее уточнение: одна Gradle-фича :flipper, разделение только пакетами api / internal / ui. Для встраивания достаточно FlipperScreen(flipper): сохранение устройства и reconnect встроены по умолчанию, клиент создаёт/закрывает хост. Прежние два AAR относятся к истории до объединения.

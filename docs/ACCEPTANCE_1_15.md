# Ручная приёмка 1.15: что проверить и как сломать

Отправка на реальный Flipper уже подтверждена пользователем 26.11.2026. Ниже проверяем регрессию и крайние случаи новой сборки, не начинаем приёмку заново с нуля.

## Перед началом

1. Записать установленную версию, Android и firmware из All info. Установить APK 1.15 поверх 1.13/1.14: приложение должно обновиться без удаления. Для старой 1.11 подпись несовместима, старый ключ утрачен. Не удалять старую установку с незавершённой очисткой ради теста обновления.
2. Взять ZIP artifacts/flipper-test-files.zip. Начать с hello.txt, empty.bin, block-513.bin, binary-1025.bin. Для отмены/фона использовать payload-64KiB.bin или собственный более крупный тестовый файл, который не успевает передаться мгновенно. Штатного размера/длительности передачи нет.
3. Использовать отдельный доступный тестовый каталог на SD, либо тестовые имена qa_*. Не выбирать рабочие NFC/SubGHz-файлы как назначение. Не запускать другого писателя в те же пути: firmware Rename не имеет атомарного no-replace.
4. Сначала пройти T01–T12: они не требуют трогать Flipper физически. Пункты с отключением связи выполнять только если её получится восстановить. Удалять системную Bluetooth-пару не нужно.
5. Для каждого теста записывать PASS / FAIL / SKIP, фактический путь из результата и причину SKIP. Процент 100% ещё не означает завершение MD5/финализации — дождаться конечного результата.

## Основной прогон

| ID | Действия | Ожидаемый результат / как понять, что сломалось |
| --- | --- | --- |
| T01 — обновление | Перед обновлением подключиться, запомнить выбранное устройство/каталог. Установить 1.15 поверх 1.14, открыть | Обновление без удаления приложения; выбор устройства сохранён. Android не сообщает конфликт подписи |
| T02 — обычная передача | Отправить hello.txt под qa_hello.txt, дождаться результата, скачать обратно | Успех с фактическим путём; MD5 совпадает, содержимое читается. Нет автоматической перезаписи уже существующего файла |
| T03 — границы | Повторить для empty.bin, block-513.bin, binary-1025.bin | Нулевой файл не зависает; размер/MD5 совпадают, бинарные байты не преобразованы |
| T04 — совпадение имён | Дважды отправить один файл под qa_collision.bin. Скачать оба результата | Появляется (2), затем (3) при повторе. Первый файл остаётся неизменным; действительный путь виден в результате |
| T05 — фактическое имя на телефоне | Дважды скачать один файл в одну папку телефона. Нажать Open saved file в результате | Провайдер подбирает имя без перезаписи; в результате показано возвращённое провайдером имя. Файл открывается подходящим приложением; при отсутствии обработчика понятная подсказка |
| T06 — отменить диалог | Открыть выбор источника и нажать Back. Выбрать источник, закрыть подтверждение отправки. Открыть сохранение и нажать Back | Никакая передача не стартует. После Close/Back старый источник не отправляется случайно |
| T07 — неверное имя | В подтверждении отправки ввести пустое имя, ../x, имя с кириллицей, больше 255 символов | Отправка недоступна, видна причина. Исправить на ASCII — можно отправить |
| T08 — уйти из файлов | Запустить передачу, нажать стрелку назад, открыть Files снова; затем перейти в Home и вернуться | Передача продолжается, каталог/позиция сохраняются. На главном компактный прогресс; подробности/отмена доступны. Второго пункта Flipper в нижнем баре нет |
| T09 — длинный список | В каталоге с большим числом файлов прокрутить вниз и запустить/наблюдать передачу | Прогресс и отмена не исчезают вместе с первой строкой списка. Стрелка назад возвращает в сводку, вверх меняет каталог |
| T10 — поворот и крупный шрифт | Повернуть телефон с открытым Files, подтверждением отправки и во время передачи. Повторить с увеличенным шрифтом/в тёмной теме | Нет второй операции, потери каталога, перекрытия кнопок или повторного подтверждения уже идущей отправки. При переполнении записать экран/масштаб |
| T11 — отменить upload | Отправить достаточно большой тестовый файл, отменить до завершения. Дождаться окончания очистки, обновить каталог, выполнить Ping | Нет ложного успеха. UUID .part удалён либо явно ожидает подключения. Сессия сохраняется, если мягкая отмена удалась, иначе восстанавливается. Если отмена попала в финализацию, конечная копия может остаться для проверки; приложение не обещает её автоматическое удаление |
| T12 — отменить download | Начать скачивание в тестовый документ, отменить. Дождаться результата, посмотреть папку телефона и список Flipper | Нет готового частичного документа. После восстановления получен настоящий List; Empty folder не показывается вместо ещё не прочитанного каталога. Затем можно передать другой файл |

## Разрешения, фон и восстановление

| ID | Действия | Ожидаемый результат / как сломать |
| --- | --- | --- |
| T13 — уведомления | Отключить уведомления приложения в Android. Запустить передачу, отказать в запросе, если он показан | Передача работает и без разрешения уведомлений. Прогресс/отмена доступны внутри приложения; отсутствие обычного уведомления не считается ошибкой передачи |
| T14 — фон и экран | Запустить файл, свернуть приложение, заблокировать экран. Подождать, вернуться; отдельно отменить из уведомления | Операция продолжилась или закончилась честной ошибкой, а не пропала. Результат/байты доступны. При отмене выполняются те же правила очистки. После окончания нет вечного уведомления активной передачи |
| T15 — запрет CONNECT | При отсутствии активной передачи отозвать Nearby devices. Android может перезапустить процесс — это нормально. Открыть приложение, выбрать/обновить известные устройства. Отказать, затем выдать доступ через App settings и нажать Try again | Отказ виден, приложение не падает. При выдаче доступа повторяется выбранное действие; ручной выбор сохранённой цели не теряется при запросе разрешений |
| T16 — документ после сохранения до передачи | Если Android показывает диалог уведомлений после выбора места сохранения, оставить его открытым и принудительно остановить приложение через настройки Android; затем открыть приложение и папку назначения | Созданный документ уже в журнале. При доступном провайдере удаляется после нового запуска. Если доступа нет — виден ожидающий cleanup, можно Retry cleanup. Если диалога нет и окно не удаётся поймать, SKIP; это не PASS |
| T17 — смерть процесса | Начать скачивание в тестовую папку и принудительно остановить приложение через настройки. Проверить файл, затем открыть приложение | Передача сама не возобновляется. На новом запуске частичный документ очищается либо видна отложенная очистка. При upload .part очищается после RPC-ready того же Flipper; неоднозначный конечный файл не удаляется автоматически |
| T18 — пропавший источник | Выбрать локальный тестовый файл для upload, перед отправкой удалить его в Files либо отключить доступное внешнее хранилище | Понятная ошибка доступа/отсутствия файла; нет ложного успеха. Выбрать новый источник — следующая операция возможна |
| T19 — недоступный провайдер | При наличии облачного/USB/сетевого провайдера начать тестовый download и лишить провайдер доступа: отключить сеть/USB. После ошибки восстановить его и нажать Retry cleanup | Если вызов действительно завис, ожидание IO ограничено примерно 30 с, закрытие — до 5 с, удаление — до 10 с; возможны отдельные 55 с восстановления RPC. UI/служба не ждут провайдер бесконечно. Пока старый вызов пишет, файл не удаляется из-под него. Cleanup повторяется после доступности. Обычный провайдер может сразу вернуть ошибку — это тоже корректно |
| T20 — Bluetooth off | Только при возможности вернуть связь: во время передачи выключить Bluetooth телефона, затем включить и выбрать Flipper | Ошибка/отмена вместо успеха; pair не удаляется. Очистка того же устройства после RPC-ready, список не остаётся ложнопустым. Сам файл целиком автоматически не повторяется |
| T21 — ручной disconnect | Во время передачи нажать Disconnect, затем подождать; после этого вручную выбрать устройство | Явное отключение имеет приоритет: автоматика не подключается вопреки нажатию. После ручного выбора снова можно работать |
| T22 — обновление кеша | Подключиться, записать Updated. Выйти/вернуться или перезапустить. Нажать refresh. После успешного upload посмотреть свободное место | Сохранённые сведения отмечены Saved snapshot и временем; неизвестное старое время не выдумывается. Refresh показывает новые данные либо ошибку, старое успешное поле не возвращается скрытно после частичного сбоя. После завершённой передачи сведения обновляются без периодического polling |

Если Flipper физически недоступен, T20 и подобные разрывы пропускаем. Не извлекать рабочую SD и не заполнять её до отказа ради теста. Ошибку места проверять только на отдельной тестовой карте/провайдере.

## Что проверяется стендом, а не ручным ожиданием

- Провайдер, полностью игнорирующий interrupt: JVM-тесты ProviderIoTest. Проверены возврат по timeout/cancel, сохранение busy до завершения работника, ограничение числа работников, закрытие позднего ресурса и отсутствие записи в уже оставленный буфер.
- Потерянный финальный ответ MD5/Rename, незавершённый RPC-кадр, подмена адреса между подтверждением и захватом сессии требуют fake transport/управляемого хоста. Нельзя засчитать их PASS только потому, что обычный файл передался.
- Release/R8 собирается автоматически; для физической проверки minified APK используется дополнительный artifacts/FlipperZeroKit-release.apk. Проверить на нём подключение, All info, Files, одну отправку/скачивание, уход в Home и уведомление. Это пробный release с той же debug-подписью, не production-релиз.

## Что прислать при FAIL

ID теста; versionName/versionCode; Android; firmware; направление; размер/имя и фактический путь; последние байты/процент; сколько ждал; текст Copy result и при проблеме связи Copy diagnostics. Указать, был ли Home/фон/поворот, какой провайдер и что именно отключал. Для UI полезен скрин/запись экрана с шагами. Не присылать приватный keystore.

Пример: T12 FAIL, 1.15 / Android 16 / firmware …; download payload-64KiB.bin, отмена на 8192 байтах; через 90 с остаётся Cleaning up; провайдер Downloads; Copy result: …

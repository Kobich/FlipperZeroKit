# Пробный прогон на Flipper

Актуальный пошаговый прогон 1.15: [ACCEPTANCE_1_15.md](ACCEPTANCE_1_15.md). Ниже сохранён расширенный исторический набор сценариев и протокольных границ.

24 ноября 2026. Прототип 1.4: один пункт Flipper в нижней навигации хоста, внутри общий экран с блоками устройства, передачи и файлов. Вся фича находится в одном :flipper; UI — внутренний блок dev.flipper.ui; подробные тесты ниже.
Реализация есть в рабочем FlipperZeroKit; mock-каталог удалён. Успешные unit-тесты и сборка не заменяют прогон на устройстве.

## Установка

Открыть FlipperZeroKit в Android Studio и запустить sample либо установить sample/build/outputs/apk/debug/sample-debug.apk. На нижнем баре один пункт Flipper; на общем экране прокручиваются блок устройства и блок файлов.
Доступных ADB-устройств при нашей проверке не было; APK на телефон автоматически не устанавливался.

## Последовательность проверки

1. В блоке устройства сначала проверить «Уже известные устройства». Список автоматически обновляется при входе; кнопка «Обновить подключённые и сопряжённые» запрашивает только разрешение подключения. Выбрать сохранённый Flipper без BLE-поиска. Если его нет, использовать отдельный поиск новых устройств. Существующий bond переиспользуется, заново подтверждать пару обычно не нужно. Дождаться Connected и RPC ACTIVE.
2. Проверить DeviceInfo и PowerInfo. Раскрыть все поля, записать firmware/ветку и заряд. Обновить сведения. Ошибка PowerInfo не должна скрывать успешный DeviceInfo.
3. Нажать Ping: должен появиться «Ping OK: … мс». Теперь результат означает полученный PingResponse. Кнопка «Скопировать диагностику» копирует сведения, RPC, ошибки и результат Ping.
4. Прокрутить к блоку «Файлы Flipper». Начальный путь /ext (SD); доступны /, /ext, /int, переход в каталоги, вверх и обновление. При отсутствии SD должна быть ошибка RPC, а не демонстрационный список.
5. Нажать небольшой файл, выбрать место сохранения через системный диалог. Дождаться результата «Сохранено, MD5 совпал». Процент 100 ещё не означает завершение проверки.
6. Открыть доступный каталог /ext. Нажать «Выбрать файл телефона», взять маленький текстовый/бинарный файл, проверить имя назначения и нажать «Отправить на Flipper». Для начала использовать ASCII-имя, например probe.txt. Существующее имя получает свободный суффикс (2), (3)…; фактический путь виден в результате. После завершающего ответа Flipper и совпадения MD5 появится «Готово», список обновится.
7. Скачать отправленный файл обратно. Проверить содержимое. Повторить для пустого файла и бинарного файла размером 1025 байт: это проверяет пустую запись, несколько блоков и последний неполный блок.
8. Отменить передачу и отдельно разорвать связь. Должны быть отмена/ошибка, а не успех. Upload старается удалить partial без разрыва; Read/сбой транспорта сбрасывает нашу сессию с автоматическим восстановлением. Очистка сохраняется до доступного устройства/провайдера; сам файл автоматически не передаётся заново.
9. После успешного подключения выйти из приложения и вернуться: выполняется ограниченная серия подключения последнего успешно подключённого устройства. Проверить также перезапуск процесса и отсутствие Flipper рядом. Ручное отключение выключает автоматику до ручного выбора устройства. Поворот Activity не считается новым входом.

На «Файлах» кнопка «Скопировать результат» сохраняет путь, состояние и результат/ошибку передачи в буфер.
Для разбора сбоя прислать скопированный текст, шаг, размер файла и при необходимости logcat по Flipper, RpcSender, DeviceViewModel, FilesViewModel. Полезно начать с пунктов 1–4; пока они не работают, большие передачи ничего не прояснят.

## Уже сопряжённый или подключённый Flipper

- В списке объединены BluetoothAdapter.bondedDevices и BluetoothManager.getConnectedDevices(GATT), без дублей по адресу. Подключённые в Android идут первыми; сопряжение отмечено отдельно. Сопряжённые устройства классического Bluetooth исключаются, BLE/dual/unknown остаются; фильтра по имени Flipper нет, чтобы не скрыть переименованное устройство.
- Это снимок состояния Android; сопряжение не доказывает доступность устройства рядом. Метка «GATT подключён в Android» не означает, что наше приложение уже имеет RPC. Нажатие открывает собственный GATT-клиент и выполняет проверку Flipper-сервиса/подписки.
- Чтение списка не запускает поиск, не сбрасывает наше соединение, не удаляет bond и не переключает Bluetooth. При возврате на экран список обновляется; кнопка позволяет повторить вручную.
- На Android 12+ нужны runtime BLUETOOTH_CONNECT для списка и прямого подключения; SCAN нужен только отдельному поиску. На API 23–30 runtime location для этого списка не запрашивается. Autoreconnect теперь также проверяет только connectPermissions.
- Если активный обмен уже идёт в другом приложении, успешный параллельный RPC не гарантируется. Системный список не позволяет передать нам чужой BluetoothGatt. В этом случае можно остановить другое приложение на телефоне, сохранив системное сопряжение; гарантировать отсутствие действий на Flipper при утраченных ключах сопряжения нельзя.
- RSSI у сохранённого/системно подключённого устройства неизвестен (null), вместо вымышленного нуля.
- Физическая проверка: открыть приложение при уже сопряжённом/подключённом Flipper, выбрать его из известного списка без поиска и проверить Ping/DeviceInfo. Дополнительно проверить отказ разрешения SCAN при выданном CONNECT, Bluetooth off и отзыв CONNECT во время обновления списка.

Основание: [bondedDevices](https://developer.android.com/reference/android/bluetooth/BluetoothAdapter#getBondedDevices()), [системные GATT-подключения](https://developer.android.com/reference/android/bluetooth/BluetoothManager#getConnectedDevices(int)).

## Решения первой версии

- Один файл и одна файловая операция одновременно. Все библиотечные Storage-вызовы проходят общий mutex: другая Storage-команда не прерывает серию записи.
- Источник и назначение телефона — URI Storage Access Framework; приложение открывает/закрывает потоки. Библиотека принимает InputStream/OutputStream, не Activity или URI.
- Путь назначения — открытый каталог плюс ASCII-имя с автоматическим подбором (2)/(3). Итоговый путь показан в результате; конкурентную запись теми же путями другим клиентом не запускаем.
- Upload: блоки по 512 байт, один command_id, has_next=true у данных, завершающий пустой блок has_next=false. Успех — финальный Empty/OK и затем совпавший Storage.Md5sum. Download: Stat → Read до has_next=false → размер → MD5.
- В памяти хранится текущий блок и ограниченный буфер входящих RPC (128 сообщений, обычно около 64 КБ файловых данных); целый файл не собирается. Переполнение явно завершает запрос ошибкой. GATT-фрагментация и flow control остаются отдельным уровнем.
- RPC-статусы сохраняют символическое имя/номер. Firmware без нужной операции вернёт ошибку; demo-подстановка отсутствует. Без подтверждённого MD5 передача не объявляется проверенной, даже если файл уже записан.
- Сведения/Ping 10 с, каталог/Stat 30 с; у Read/Write нет общего лимита (0), но есть watchdog отсутствия активности 60 с и таймауты транспорта. Финальный MD5/публикация ждут при живой сессии. Перед обнаружением GATT-сервисов клиент запрашивает MTU 512 и использует фактически согласованный размер.
- Foreground connectedDevice service реализован; очереди/resume нет. Задача не зависит от UI ViewModel и продолжается в живом процессе; смерть процесса требует новой целой передачи после очистки.
- Upload при отмене старается очистить provisional-файлы без разрыва; Read/неисправный транспорт — со сбросом и восстановлением. Неуспешная очистка сохраняется для доступного устройства/провайдера; явное действие пользователя имеет приоритет.
- Версия firmware устройства пока неизвестна. Совместимость на Android 16 и реальном Flipper требует прогона.

## Конфликт имён, очистка и отмена

При отправке на Flipper путь подбирается автоматически: /ext/file.txt, /ext/file (2).txt, /ext/file (3).txt… Итоговый путь возвращается в TransferResult.path и показан после завершения. При скачивании конфликт локального имени обрабатывает системный SAF-провайдер. Для upload временный UUID-файл сначала проходит MD5; затем публикуется свободное имя и проверяется финальная копия. Firmware Rename может выполнять copy/delete, поэтому финализация не обещана атомарной против внешнего параллельного писателя; во время прогона другим клиентом те же пути не менять.

Сопряжение — сохранённые ключи, GATT/RPC — текущая клиентская сессия. Они различаются: закрытие нашей сессии не удаляет пару. Upload отменяется на границе целого RPC-кадра и старается удалить provisional-файлы через Storage.Delete без разрыва. При неудаче транспорта/очистки — ограниченное восстановление. Отдельной команды Read.Cancel в используемом протоколе нет, поэтому отмена скачивания сбрасывает сессию и восстанавливает её.

Частичные файлы удаляются; при физически недоступном устройстве задача сохранена по его адресу и повторится после RPC-ready. На телефоне журналируются созданные SAF-документы и дополнительные URI-grants: при сбое или следующем запуске после смерти процесса они очищаются, если провайдер доступен. Ошибка удаления остаётся видимой, а не считается успехом. Операция не resume-ится: следующий запуск — передача целого файла.

Передача принадлежит foreground service connectedDevice: сворачивание, блокировка и удаление UI destination не отменяют живую операцию. Есть уведомление с прогрессом/отменой и конечным результатом. Смерть процесса/Force stop завершают операцию; автоматического возобновления данных нет. Клиент Flipper в хосте должен жить до завершения операции, а не close() при смене экрана.

Общего лимита 10 минут больше нет. Потоковый обмен контролирует отсутствие активности в течение 60 с; отдельные Bluetooth/metadata/cleanup-запросы имеют технические таймауты. Финальный MD5/публикация ждут пока жива сессия и могут быть отменены. Один файл, ASCII-имена, каталоги не ограничены приложением; ограничения firmware/FS/свободного места остаются.

Стандартная политика reconnect: до 3 попыток с паузами 0/2/6 с в видимой фиче, cooldown 60 с после провала до нового входа либо ручной выбор. Нет бесконечного сканирования/reconnect в фоне без операции; явный disconnect/новый поиск останавливает автоматику до ручного выбора. Это выбранные пробные интервалы, требующие UX-проверки на телефоне.

## Подготовка ручных тестов

1. Сначала записать Android, versionName/versionCode APK, firmware/ветку из DeviceInfo и путь каталога. Положительный прогон 1.1 подтверждает скачивание, но после переноса UI регрессию проверить снова.
2. Работать с тестовыми именами в доступном каталоге /ext, например qa_01_hello.txt. Для повторного прогона можно оставить имя: приложение подберёт (2)/(3); записать фактический путь из результата. Не использовать рабочие NFC/SubGHz-файлы как цели записи.
3. Скопировать на телефон контрольные файлы из test-data/manual; готовый архив — artifacts/flipper-test-files.zip. Распаковать его обычным файловым менеджером телефона и выбирать файлы через системный picker.
4. После каждого завершения проверять именно «Готово/Сохранено, MD5 совпал», затем результат/содержимое; 100% байтов ещё не означает завершённую RPC/MD5-проверку.
5. Результат каждого пункта: PASS, FAIL, BLOCKED (нет нужного устройства/провайдера/доступа) или NOT RUN. Наличие теста в этом документе не означает, что он уже выполнен.

## Как прислать результат теста

- ID теста, PASS/FAIL/BLOCKED, точные действия.
- APK versionName/versionCode, Android, firmware/ветка из скопированного DeviceInfo.
- Направление передачи, исходный и целевой путь, размер, последнее число байтов/процент, ожидаемый и показанный MD5.
- Ожидание и фактическое поведение; сохранился ли bond/была ли наша RPC-сессия готова после сбоя.
- «Скопировать диагностику» и «Скопировать результат», при необходимости logcat: Flipper, RpcSender, DeviceViewModel, FilesViewModel.

Начать с A06/A07 и U01–U04. B01–B14 не считать проверенными по успешному обычному скачиванию; выполнять отдельно при возможности восстановления связи.


## UI 1.13 — отдельный экран файлов

1. Открыть главный экран: полный список/панель файлов отсутствуют; Open files открывает внутреннюю страницу Files. Память SD остаётся в сводке.
2. Открыть вложенный каталог, прокрутить список, вернуться стрелкой и открыть Files снова: путь и позиция списка сохранены. Системный Back возвращает в сводку, кнопка вверх меняет каталог.
3. Выбрать файл телефона с именем уже существующего файла на Flipper. После чтения имени и размера Upload становится доступной. Close, Back и касание вне окна возвращают к каталогу без индикатора подготовки, после чего файл можно выбрать заново. При подтверждении занятое имя получает суффикс `(2)`, `(3)` и далее.
4. Начать upload/download, вернуться на главный: компактная карточка прогресса открывает подробности и отмену. Возврат в Files сохраняет текущую передачу. После завершения открыть **History** на главном экране. Операция появляется один раз с временем и итогом. Повторить с отменой и ошибкой. Проверить порядок от новых к старым, копирование результата, системный Back, стрелку и сохранение истории после перезапуска приложения. До первой передачи виден текст **No transfers yet.**
5. Повернуть телефон с диалогом, на обеих страницах и во время передачи; проверить крупный шрифт/ландшафт, переполнение длинных путей и результата.
6. Проверить offline/ошибку SD и переподключение на экране Files. Существующее блокирующее окно cleanup/recovery сохраняется.


## Регрессия 1.14 после ревью

- Отмена upload: UUID .part удалён либо ожидает reconnect; неоднозначный конечный файл не удаляется автоматически. Существующее имя получает (2)/(3); сторонним клиентом те же пути одновременно не писать. При ошибке финализации проверить указанный путь вручную.
- Длительный upload с прогрессом не ограничен 10 минутами. MD5/Rename имеют отдельный технический предел 2–15 минут по размеру. Проверять потерянный ответ на fake transport/firmware; не требовать физически висеть весь срок.
- Во время системного диалога уведомлений/открытия источника переключить устройство через тестовый хост: передача на другой адрес должна завершиться ошибкой до файловых команд. Тот же адрес проверяется под Storage lock для List/Read/Write.
- После отмены/сбоя с восстановлением каталог обновляется; до первого ответа List не показывается Empty folder. В длинном списке отмена/прогресс остаются над списком.
- После отзыва CONNECT выбрать сохранённое устройство: виден текст о разрешении вместо молчаливого отказа.
- Сбой кредитов flow control внутри кадра проверять тестовым транспортом: сессия закрывается, Delete не уходит в незавершённый кадр.

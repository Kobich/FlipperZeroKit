# Пробный прогон на Flipper

24 ноября 2026. Прототип 1.3: один пункт Flipper в нижней навигации хоста, внутри вкладки «Устройство» и «Файлы». Вся фича находится в одном :flipper; UI — внутренний блок dev.flipper.ui; подробные тесты ниже.
Реализация есть в рабочем FlipperZeroKit; mock-каталог удалён. Успешные unit-тесты и сборка не заменяют прогон на устройстве.

## Установка

Открыть FlipperZeroKit в Android Studio и запустить sample либо установить sample/build/outputs/apk/debug/sample-debug.apk. На нижнем баре один пункт Flipper; разделы устройства и файлов выбираются верхними вкладками.
Доступных ADB-устройств при нашей проверке не было; APK на телефон автоматически не устанавливался.

## Последовательность проверки

1. На вкладке устройства сначала проверить «Уже известные устройства». Список автоматически обновляется при входе; кнопка «Обновить подключённые и сопряжённые» запрашивает только разрешение подключения. Выбрать сохранённый Flipper без BLE-поиска. Если его нет, использовать отдельный поиск новых устройств. Существующий bond переиспользуется, заново подтверждать пару обычно не нужно. Дождаться Connected и RPC ACTIVE.
2. Проверить DeviceInfo и PowerInfo. Раскрыть все поля, записать firmware/ветку и заряд. Обновить сведения. Ошибка PowerInfo не должна скрывать успешный DeviceInfo.
3. Нажать Ping: должен появиться «Ping OK: … мс». Теперь результат означает полученный PingResponse. Кнопка «Скопировать диагностику» копирует сведения, RPC, ошибки и результат Ping.
4. Открыть «Файлы». Начальный путь /ext (SD); доступны /, /ext, /int, переход в каталоги, вверх и обновление. При отсутствии SD должна быть ошибка RPC, а не демонстрационный список.
5. Нажать небольшой файл, выбрать место сохранения через системный диалог. Дождаться результата «Сохранено, MD5 совпал». Процент 100 ещё не означает завершение проверки.
6. Открыть доступный каталог /ext. Нажать «Выбрать файл телефона», взять маленький текстовый/бинарный файл, проверить имя назначения и нажать «Отправить на Flipper». Для начала использовать ASCII-имя, например probe.txt. Существующее имя отклоняется. После завершающего ответа Flipper и совпадения MD5 появится «Готово», список обновится.
7. Скачать отправленный файл обратно. Проверить содержимое. Повторить для пустого файла и бинарного файла размером 1025 байт: это проверяет пустую запись, несколько блоков и последний неполный блок.
8. Отменить передачу и отдельно разорвать связь. Должны быть отмена/ошибка, а не успех. После прерванной передачи сессия закрывается: подключиться снова. Частичный документ телефона приложение пытается удалить; при невозможности показывает необходимость ручного удаления. Частичный файл Flipper автоматически не удаляется — для повтора выбрать другое имя.
9. После успешного подключения выйти из приложения и вернуться: выполняется одна попытка подключения последнего успешно подключённого устройства. Проверить также перезапуск процесса и отсутствие Flipper рядом. Ручное отключение не вызывает немедленного reconnect; новый вход снова разрешает попытку. Поворот Activity не считается новым входом.

На «Файлах» кнопка «Скопировать результат» сохраняет путь, состояние и результат/ошибку передачи в буфер.
Для разбора сбоя прислать скопированный текст, шаг, размер файла и при необходимости logcat по Flipper, RpcSender, DeviceViewModel, FilesViewModel. Полезно начать с пунктов 1–4; пока они не работают, большие передачи ничего не прояснят.

## Уже сопряжённый или подключённый Flipper

- В списке объединены BluetoothAdapter.bondedDevices и BluetoothManager.getConnectedDevices(GATT), без дублей по адресу. Подключённые в Android идут первыми; сопряжение отмечено отдельно. Сопряжённые устройства классического Bluetooth исключаются, BLE/dual/unknown остаются; фильтра по имени Flipper нет, чтобы не скрыть переименованное устройство.
- Это снимок состояния Android; сопряжение не доказывает доступность устройства рядом. Метка «GATT подключён в Android» не означает, что наше приложение уже имеет RPC. Нажатие открывает собственный GATT-клиент и выполняет проверку Flipper-сервиса/подписки.
- Чтение списка не запускает поиск, не сбрасывает наше соединение, не удаляет bond и не переключает Bluetooth. При возврате на экран список обновляется; кнопка позволяет повторить вручную.
- На Android 12+ нужны runtime BLUETOOTH_CONNECT для списка и прямого подключения; SCAN нужен только отдельному поиску. На API 23–30 runtime location для этого списка не запрашивается. Autoreconnect теперь также проверяет только connectPermissions.
- Если активный обмен уже идёт в другом приложении, успешный параллельный RPC не гарантируется. Системный список не позволяет передать нам чужой BluetoothGatt. В этом случае можно остановить другое приложение на телефоне, сохранив системное сопряжение; гарантировать отсутствие действий на Flipper при утраченных ключах сопряжения нельзя.
- RSSI у сохранённого/системно подключённого устройства неизвестен (null), вместо вымышленного нуля.
- Физическая проверка: открыть приложение при уже сопряжённом/подключённом Flipper, выбрать его из известного списка без поиска и проверить Ping/DeviceInfo. Дополнительно проверить отказ разрешения SCAN при выданном CONNECT, Bluetooth off и отзыв CONNECT во время обновления списка.

Основание: [bondedDevices](https://developer.android.com/reference/android/bluetooth/BluetoothAdapter#getBondedDevices()), [системные GATT-подключения](https://developer.android.com/reference/android/bluetooth/BluetoothManager#getConnectedDevices(int)).

## Решения первой версии

- Один файл и одна файловая операция одновременно. Все библиотечные Storage-вызовы проходят общий mutex: другая Storage-команда не прерывает серию записи.
- Источник и назначение телефона — URI Storage Access Framework; приложение открывает/закрывает потоки. Библиотека принимает InputStream/OutputStream, не Activity или URI.
- Путь назначения — открытый каталог плюс редактируемое ASCII-имя. Перезапись выключена через предварительный Stat. Это проверка существования, а не атомарное создание: внешняя запись между Stat и Write не исключается протоколом.
- Upload: блоки по 512 байт, один command_id, has_next=true у данных, завершающий пустой блок has_next=false. Успех — финальный Empty/OK и затем совпавший Storage.Md5sum. Download: Stat → Read до has_next=false → размер → MD5.
- В памяти хранится текущий блок и ограниченный буфер входящих RPC (128 сообщений, обычно около 64 КБ файловых данных); целый файл не собирается. Переполнение явно завершает запрос ошибкой. GATT-фрагментация и flow control остаются отдельным уровнем.
- RPC-статусы сохраняют символическое имя/номер. Firmware без нужной операции вернёт ошибку; demo-подстановка отсутствует. Без подтверждённого MD5 передача не объявляется проверенной, даже если файл уже записан.
- Timeout сведений/Ping 10 с, каталога/Stat 30 с, MD5 60 с, Read/Write 10 минут на обмен. Это абсолютные пределы, не обещание скорости; MTU пока автоматически не увеличиваем.
- Foreground service, очередь, resume и восстановление передачи после смерти процесса не реализованы. При уходе в фон операция может продолжаться, пока жив процесс/ViewModel; гарантий фоновой передачи нет.
- При ошибке/отмене начавшейся передачи закрываем текущую GATT-сессию, чтобы сбросить состояние прошивки. Уже созданный на Flipper частичный файл может остаться. Автоматического удаления и перезаписи нет.
- Версия firmware устройства пока неизвестна. Совместимость на Android 16 и реальном Flipper требует прогона.

## Что означает «без перезаписи» и «соединение прервано»

«Без перезаписи» относится к отправке на Flipper: если по целевому пути уже есть файл/каталог, предварительный Storage.Stat отклоняет запись. Пример: /ext/probe.txt уже существует → отправка в /ext/probe.txt завершается ошибкой → нужно выбрать probe_2.txt или другой каталог. Выбор другого локального файла с тем же именем ничего не меняет: конфликт определяется путём на Flipper. Сейчас нет действия «Заменить». Проверка Stat не является атомарной гарантией против внешнего изменения файла между Stat и Write.

Сопряжение — сохранённые ключи доверия телефона и Flipper. GATT — открытое Bluetooth-соединение клиента. RPC — канал команд поверх него. Закрытие клиентской GATT/RPC-сессии не удаляет сопряжение и не выключает Bluetooth телефона.

Прервать передачу может потеря радиосвязи, выключенный Bluetooth/Flipper, ошибка чтения/записи или нажатие «Отменить передачу». Если отмена/ошибка произошла внутри начавшегося Storage.Read/Write, библиотека намеренно закрывает свою текущую GATT/RPC-сессию, чтобы прошивка не оставалась в незавершённой файловой операции. Это политика нынешнего прототипа, а не требование повторно создавать пару. После сброса нужно снова открыть соединение из известного списка. На телефоне частичный документ пытаемся удалить, на Flipper частичный файл может остаться; для повтора — новое имя.

Ошибка имени, уже существующий путь или отмена системного picker до начала файлового обмена не требуют такого сброса. Один лишь переход между «Устройство» и «Файлы» передачу не отменяет.

## Подготовка ручных тестов

1. Сначала записать Android, versionName/versionCode APK, firmware/ветку из DeviceInfo и путь каталога. Положительный прогон 1.1 подтверждает скачивание, но после переноса UI регрессию проверить снова.
2. Работать с тестовыми именами в доступном каталоге /ext, например qa_01_hello.txt. Для повторного прогона менять префикс: существующие имена сейчас отклоняются. Не использовать рабочие NFC/SubGHz-файлы как цели записи.
3. Скопировать на телефон контрольные файлы из test-data/manual; готовый архив — artifacts/flipper-test-files.zip. Распаковать его обычным файловым менеджером телефона и выбирать файлы через системный picker.
4. После каждого завершения проверять именно «Готово/Сохранено, MD5 совпал», затем результат/содержимое; 100% байтов ещё не означает завершённую RPC/MD5-проверку.
5. Результат каждого пункта: PASS, FAIL, BLOCKED (нет нужного устройства/провайдера/доступа) или NOT RUN. Наличие теста в этом документе не означает, что он уже выполнен.

### B. Разрывы и восстановление — выполнять с возможностью восстановить устройство

Не удалять сохранённую пару ради этих тестов. Новое сопряжение и действие «Забыть устройство» — отдельная физическая проверка, которая может потребовать подтверждения на самом Flipper. Не извлекать SD во время записи.

| ID | Как воспроизвести | Ожидаемый результат |
| --- | --- | --- |
| B01 — отмена скачивания | Начать скачивание достаточно большого тестового файла; когда байты пошли, нажать «Отменить передачу». | «Отменено», успех не показывается; наша сессия закрывается. Частичный документ телефона удалён либо явно предложено удалить его вручную. После нового соединения повтор работает. |
| B02 — отмена отправки | Отправлять большой тестовый файл под новым именем; после начала прогресса отменить. Затем подключиться снова и обновить список. | Отмена и закрытая клиентская сессия, без «MD5 совпал». Частичный файл на Flipper может быть виден; повтор в тот же путь отклоняется, новое имя позволяет повторить. |
| B03 — ручное отключение во время передачи | Во время тестовой передачи открыть внутреннюю вкладку «Устройство» → «Отключить устройство». | Передача завершается ошибкой/отменой, не успехом. Bond остаётся; кнопки RPC отключены. Немедленного автоматического reconnect в той же видимой фиче нет. |
| B04 — Bluetooth телефона выключен | Во время соединения/передачи выключить Bluetooth телефона. Вернуться в UI; затем включить Bluetooth и выбрать Flipper из известных. | Конечная ошибка/отключение, нет бесконечного успеха/прогресса; после нового соединения повтор возможен. Точный момент срабатывания зависит от Bluetooth callback/таймаута. |
| B05 — физическая потеря связи | Во время передачи выключить тестовый Flipper либо унести его за радиус действия. После ошибки вернуть устройство и подключиться снова. | Ошибка/timeout без объявления сохранённого проверенного файла. Частичный результат обработан как в B01/B02; после возврата можно повторить. |
| B06 — reconnect при входе | Успешно подключиться, выйти из фичи/приложения и вернуться. Отдельно перезапустить процесс. Повторить после ручного disconnect с последующим выходом и возвратом. | Одна попытка последнего устройства на вход, без параллельных клиентов. Ручной disconnect не отменяется сам собой, пока остаёмся в фиче; новый вход снова разрешает попытку. Поворот не считается новым входом. |
| B07 — устройство недоступно | После успешного подключения сохранить пару, выключить Flipper; перезапустить приложение. | Контролируемая попытка заканчивается ошибкой/таймаутом, UI остаётся пригодным для ручного повтора. Не бесконечная серия подключений. |
| B08 — отказ/отзыв разрешения | При доступе к восстановлению запретить приложению Nearby devices/Bluetooth в настройках Android; запустить заново и открыть известный список. Затем выдать разрешение и повторить. | Понятный отказ без SecurityException в UI; после выдачи список/подключение работают. Android может сам завершить процесс при отзыве — это не crash приложения. Отдельное CONNECT без SCAN не всегда воспроизводится обычным системным переключателем группы разрешений; для этого нужен тестовый хост/ADB. |
| B09 — отказ включать Bluetooth | При выключенном Bluetooth нажать обновление известных устройств/поиск, отменить системное предложение включения. Затем повторить и согласиться. | Сначала понятное сообщение об отказе, затем возможность продолжить. Нет автоматического переключения Bluetooth без системного UI. |
| B10 — недоступная SD/каталог | С тестовым Flipper без рабочей SD открыть /ext; отдельно открыть существующий пустой каталог, подготовленный заранее. | Отсутствие SD даёт RPC-ошибку, настоящий пустой каталог — успешный пустой список. Для этих состояний UI не показывает одинаковое «пусто». |
| B11 — много файлов | На тестовой SD заранее создать каталог с 100+ мелкими файлами; открыть и обновить его в приложении. | Все пакеты Storage.List собраны до конца серии; количество/имена совпадают, нет частичного успешного списка и зависания. |
| B12 — файл исчез после списка | В списке выбрать тестовый файл, а перед подтверждением сохранения удалить именно этот файл на устройстве другим доступным инструментом. | Отсутствующий файл приводит к ошибке Stat/Read; созданный частичный документ телефона не объявляется готовым. Если другой инструмент нельзя использовать без смены сессии, зафиксировать реальный сценарий, а не требовать конкретный код ошибки. |
| B13 — нехватка места/запрет записи | Только на отдельной тестовой SD или управляемом тестовом хранилище создать недостаток места/отказ доступа, затем отправить файл больше свободного места. Не заполнять рабочую SD ради теста. | RPC-ошибка/ошибка записи, без ложного успеха; возможный частичный файл отмечен. Нет условия для безопасного воспроизведения — BLOCKED. |
| B14 — новый bond | При физическом доступе взять ранее не сопряжённый тестовый Flipper, найти и подтвердить пару; отдельно проверить отказ подтверждения. | Успех создаёт канал; отказ/timeout даёт понятный результат и ручной повтор. Действующую рабочую пару пользователя для этого не удаляем. |

### P. Ошибки протокола, которые не воспроизводятся надёжно обычными кнопками APK

| ID | Как воспроизвести | Ожидаемый результат и текущий статус |
| --- | --- | --- |
| P01 — нет ответа/оборванная серия | На компьютере запустить тесты RpcClientTest, в том числе timeoutAlsoCoversABlockedSend и timesOutWithoutReturningPartialDataAndCanRetry. Для UI нужен fake transport/тестовая firmware, которая не завершает ответ. | Запрос заканчивается TIMEOUT, частичные сведения не возвращаются; поздний ответ не попадает в повторный запрос. Unit-сценарии уже есть, физический timeout сам по себе этим не подтверждён. |
| P02 — статус/тип/ранний ACK/переполнение | Запустить StorageRpcTest и RpcClientTest: неправильный ответ, remote error, write без финального ACK, преждевременный ACK, overflow и session close. | Явная ошибка, нет тихой потери пакетов/ложного успеха; отправитель отменяется при ошибке. Эти сценарии покрыты существующими unit-тестами. |
| P03 — GATT есть, RPC ACTIVE нет | Нужен управляемый fake GATT или тестовая firmware: завершить CCCD, но оставить RPC NOT_ACTIVE/не вернуть состояние. | Целевой результат — конечная ошибка подготовки. Известный незакрытый пункт: отдельного таймаута этого состояния в DefaultFlipper пока нет; тест ожидаемо может выявить бесконечное ожидание UI. Не выдавать за уже исправленное. |
| P04 — MD5 mismatch/ошибка потока | В тестовом хосте подать OutputStream/InputStream, выбрасывающий IOException после N байт; отдельно подменить ответ Storage.Md5sum корректной по формату, но другой суммой. Обычный APK такого переключателя не имеет. | Ошибка, не «MD5 совпал»; текущая сессия сброшена после начавшейся передачи, частичный результат обработан. Для полного воспроизведения нужен интеграционный стенд; проверки формата MD5 в unit-тесте не заменяют этот сценарий. |

Команда для существующих RPC unit-тестов:

    .\gradlew.bat :flipper:testDebugUnitTest --tests "*RpcClientTest" --tests "*StorageRpcTest"

## Как прислать результат теста

- ID теста, PASS/FAIL/BLOCKED, точные действия.
- APK versionName/versionCode, Android, firmware/ветка из скопированного DeviceInfo.
- Направление передачи, исходный и целевой путь, размер, последнее число байтов/процент, ожидаемый и показанный MD5.
- Ожидание и фактическое поведение; сохранился ли bond/была ли наша RPC-сессия готова после сбоя.
- «Скопировать диагностику» и «Скопировать результат», при необходимости logcat: Flipper, RpcSender, DeviceViewModel, FilesViewModel.

Начать с A06/A07 и U01–U04. B01–B14 не считать проверенными по успешному обычному скачиванию; выполнять отдельно при возможности восстановления связи.

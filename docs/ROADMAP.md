## Порядок этапов

| Этап | Требования | Результат |
| --- | --- | --- |
| P0. Подтвердить текущую базу | R01, R03, R07 | Наш APK подключается, RPC готов, DeviceInfo читается и обновляется на настоящем устройстве |
| P1. Восстановление соединения | R01, R02 | При повторном входе есть ограниченная автоматическая попытка подключения к последнему устройству |
| P2. Сведения и заряд | R03, R07 | DeviceInfo + PowerInfo показывают настоящие характеристики и заряд |
| P3. Каталоги Flipper | R04, R07 | Реальный список файлов с навигацией, обновлением и обработкой ошибок |
| P4. Получение файла | R05, R07, R08 | Файл скачивается на телефон потоком, с прогрессом и проверенным результатом |
| P5. Отправка файла | R06, R07, R08 | Выбранный файл телефона записывается на Flipper и проходит проверку содержимого |
| P6. Приёмка приложения | R01–R08 | Полный пользовательский путь подтверждён на Android 16 и зафиксированной firmware |

Базовая зависимость: P0 → P1 → P2 → P3 → P4 → P5 → P6. Общая обработка файловой операции и прогресса появляется в P4 и переиспользуется в P5.
Запись на устройство вводится после работающего чтения и сверки протокола Storage.Write.

- [ ] При сбое зафиксировать сообщение UI и логи Flipper/DeviceViewModel, исправить и повторить нужный сценарий.
- [ ] Закрепить совместимую upstream-версию proto-схем по установленной firmware; записать происхождение и версию.

Критерий выхода: базовый запрос реально работает после повторного подключения, ошибки не оставляют зависшую загрузку. Чек-лист — [DEVICE_INFO.md](DEVICE_INFO.md).

Отдельный существующий технический долг: завершить AAR/Lint после доступности инструментов, согласовать toolchain для compileSdk 37. Он записывается отдельно от функциональных результатов; сборку APK не выдаём за прохождение Lint.

- [ ] Согласовать путь назначения и политику совпадающих имён; показать пользователю, какой файл и куда отправляется.

- [ ] Переиспользовать модель прогресса/ошибок/отмены из P4; объявлять успех после завершающего протокольного подтверждения.

## Правила ведения плана

- Новая функциональность сначала связывается с R01–R08 или оформляется явным уточнением TASK.md.
- Галочка означает конкретный выполненный пункт, а не завершение всего требования по факту наличия proto-сообщения или mock-экрана.
- Для BLE/файлов различать unit-тесты и проверку на физическом Flipper; успешная сборка не заменяет второй результат.
- После каждого этапа обновлять этот план и VALIDATION.md. История исходной базы хранится в BASELINE.md, детали DeviceInfo — в DEVICE_INFO.md.

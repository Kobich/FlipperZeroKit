1. Проверить уже реализованную отправку: маленький файл с уникальным ASCII-именем → финальный ответ/MD5 → обновлённый список → скачивание обратно и сверка содержимого. R06 пока нельзя считать физически закрытым.
2. Проверить ошибку подготовки RPC при отсутствии PingResponse и возврат из фона по [записи от 25 ноября](VALIDATION.md#25-ноября-2026--скачки-экрана-и-ложный-rpc-active-после-возврата). На подготовку отводится до 15 с после CCCD. Затем прогнать политики очистки и восстановления.
3. Подтвердить autoreconnect: возврат, перезапуск процесса, ручной disconnect, недоступный Flipper. Код написан; отдельной физической отметки нет.
4. Пройти ошибки/границы: отмена, обрыв, отказ CONNECT/SCAN, Bluetooth off, недоступная SD/каталог, конфликт имени, пустой/бинарный/крупный файл; проверить честный конечный результат и судьбу частичного файла.
5. Записать firmware из DeviceInfo и контрольные результаты; прогнать новую UI-фичу по U01–U06 и F01–F06. Архитектура: один :flipper с ui/, один пункт в баре хоста, общий экран с блоками. Передача принадлежит foreground service. Затем довести UI/ошибки по результатам и подключить библиотеку в целевой проект.

Очередь, несколько файлов, resume и произвольные действия файлового менеджера — отдельные расширения. Фон, автонумерация, очистка и восстановление теперь явно включены пользователем в текущий объём; их физическая приёмка входит в текущий остаток. ASCII-ограничение и скорость BLE/MTU сначала оцениваем на реальных сценариях.

## Порядок этапов

| Этап | Требования | Результат |
| --- | --- | --- |
| P0. Подтвердить текущую базу | R01, R03, R07 | Наш APK подключается, RPC готов, DeviceInfo читается и обновляется на настоящем устройстве |
| P1. Восстановление соединения | R01, R02 | При повторном входе есть ограниченная автоматическая попытка подключения к последнему устройству |
| P2. Сведения и заряд | R03, R07 | DeviceInfo + PowerInfo показывают настоящие характеристики и заряд |
| P3. Каталоги Flipper | R04, R07 | Реальный список файлов с навигацией, обновлением и обработкой ошибок |
| P4. Получение файла | R05, R07, R08 | Файл скачивается на телефон потоком, с прогрессом и проверенным результатом |
| P5. Отправка файла | R06, R07, R08 | Выбранный файл телефона записывается на Flipper и проходит проверку содержимого |
| P6. Приёмка приложения | R01–R09 | Полный пользовательский путь подтверждён на Android 16 и зафиксированной firmware |

Базовая зависимость: P0 → P1 → P2 → P3 → P4 → P5 → P6. Общая обработка файловой операции и прогресса появляется в P4 и переиспользуется в P5.
По запросу пользователя 24.11.2026 код P1–P5 подготовлен одним пробным вариантом после сверки протокола; первый пользовательский прогон уже положительный, но полная приёмка P0–P6 остаётся открыта. Порядок прогона — [PROTOTYPE.md](PROTOTYPE.md).

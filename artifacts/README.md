- Application ID: dev.flipper.zerokit.sample.
- Version: 1.14-prototype, code 15.

Единая библиотека :flipper включает BLE/RPC, файлы и UI-блок ui; отдельного UI Gradle-модуля нет. FlipperScreen(flipper) — один общий экран с текущими блоками устройства/передачи/файлов.

**Важно для установки:** APK 1.13–1.14 подписаны одним локальным debug-ключом, отличающимся от облачного ключа 1.5–1.12. Для обновления с сохранением данных нужна сборка новым исходником со старым ключом. Этот APK не установится поверх 1.11/1.12; удаление установленного приложения удалит его настройки и журналы незавершённой очистки.

В 1.14 внесены точечные исправления передачи: очистка только UUID .part, проверка выбранного адреса под Storage lock, ограничение ожидания SD-финализации, сброс частичного RPC-кадра при потере кредитов, устранение общего лимита upload и ложного Empty folder. Прогресс/отмена закреплены над списком. 46 тестов, AAR/APK и оба Lint прошли. [Сделанное и оставшиеся ограничения](../docs/FIXES_1_14.md). Параллельный внешний писатель по тому же пути не поддержан; неоднозначное конечное назначение не удаляется автоматически.

В 1.13 браузер вынесен во внутренний экран Files. На главном Open files и компактный статус передачи с подробностями по нажатию. Перед отправкой — диалог имени/назначения. Back возвращает в сводку, передача продолжается. 42 unit-теста, AAR/APK и оба Lint прошли; UI на телефоне ещё не проверен.

В 1.12 убрана верхняя панель **Flipper** с переключателем темы. Приложение использует светлый или тёмный режим Android. Прошли 42 unit-теста. [Хронология](../docs/VALIDATION.md#25-ноября-2026--системная-тема-без-верхней-панели)

В 1.11 возвращён компактный Bluetooth-поиск. **Ping**, обновление и отключение находятся в шапке сводки. **All info** открывает внутреннюю страницу с **Power Info** и остальными сведениями. Прошли 42 unit-теста. [Хронология](../docs/VALIDATION.md#25-ноября-2026--шапка-устройства-и-страница-all-info)

В 1.10 файловый браузер получил одну строку навигации и компактный список с иконками и размерами файлов. Bluetooth-поиск вернулся к компоновке 1.8. Прошли 42 unit-теста. [Хронология](../docs/VALIDATION.md#25-ноября-2026--компактный-файловый-браузер)

В 1.9 выбор Bluetooth-устройства занимает одну компактную панель. Найденные устройства с известными адресами не дублируются. Первые четыре новых устройства видны сразу, остальные раскрываются по кнопке. Прошли 42 unit-теста. [Хронология](../docs/VALIDATION.md#25-ноября-2026--компактный-выбор-bluetooth-устройств)

В 1.8 восстановление передачи и очистка частичного файла блокируют экран диалогом с круговым индикатором. Диалог закрывается по завершении попытки. Прошли 42 unit-теста. [Хронология](../docs/VALIDATION.md#25-ноября-2026--модальный-диалог-восстановления-передачи)

В 1.7 весь интерфейс переведён на английский, включая уведомления. Действия **Ping**, **Power Info**, обновление сведений и отключение собраны в одну строку. Прошли 42 unit-теста. [Хронология](../docs/VALIDATION.md#25-ноября-2026--английский-интерфейс-и-компактная-строка-действий)

В 1.6 появилась компактная сводка с зарядом, прошивкой и объёмом SD-карты. Сведения сохраняются на телефоне. Новый запрос выполняется по кнопке после первой загрузки. Прошли 42 unit-теста. [Хронология](../docs/VALIDATION.md#25-ноября-2026--краткая-сводка-устройства-и-сохранение-сведений)

В 1.5 готовность RPC подтверждается ответом Ping, ручной выбор сохраняется сразу, а согласование MTU выполняется перед обнаружением GATT-сервисов. Отчёт о подключении содержит этапы и коды ошибок. Прошли 40 unit-тестов. Проверка подключения к Libam на Android 16 предстоит. [Хронология](../docs/VALIDATION.md#25-ноября-2026--libam-подключается-и-сразу-теряет-rpc)

APK 1.5–1.12 подписаны одним облачным debug-ключом. Для установки после опубликованного APK 1.4 с другой подписью потребуется сначала удалить установленную версию.

В 1.4 добавлены автонумерация (2)/(3), журналы очистки partial, мягкая отмена upload с fallback восстановления, foreground connectedDevice-передача с уведомлением и отменой, ограниченный reconnect без фонового polling. Общего лимита длительности передачи нет; технические таймауты обмена сохраняются. Клиент хоста должен жить до конца операции.
